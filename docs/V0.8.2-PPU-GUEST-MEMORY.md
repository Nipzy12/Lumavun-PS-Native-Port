# V0.8.2: PPC64 Homebrew Guest-Memory Translation

V0.8.2 extends the **original, self-authored PPC64 homebrew ELF** to execute real memory load and store instructions after static translation to Windows x64 C++. It is not a PlayStation 3 memory-manager implementation or a compatible retail game runtime.

## Executable behavior

The ELF performs a PowerPC loop to calculate 1+2+3+4+5, calls a subroutine, and then uses these real instruction encodings:

| PPC64 instruction | Implemented homebrew behavior |
| --- | --- |
| `std` | Store low 64 bits, big-endian, 8-byte aligned |
| `ld` | Load 64 bits, big-endian, 8-byte aligned |
| `stw` | Store low 32 bits, big-endian, 4-byte aligned |
| `lwz` | Load unsigned 32-bit, zero-extended to 64 bits |
| `lbz` | Load one unsigned byte, no alignment beyond one byte |

Each supported load/store becomes a **host C++ statement** invoking a checked byte-array helper. There is no PowerPC instruction decoder/emulator at runtime. Unsupported DS-form updates, unknown instructions, invalid branch targets and malformed ELF inputs are rejected during translation.

The demo's sandboxed guest RAM is a zero-initialized **64 KiB** byte array mapped to guest addresses `0x2000` to `0x11FFF` (inclusive). This is a **fictional test address space**. It does not model PS3 CellOS virtual memory, RSX MMIO, Sony memory protection, real thread stacks, SPU local store or paging.

Out-of-range or incorrectly aligned accesses terminate the generated native executable with status **12**, rather than dereferencing untrusted guest addresses through native pointers. Arithmetic uses unsigned 64-bit guest addresses; a wrap below the mapping base fails the range check.

## Evidence from the native executable

Run `LumavunPPUHomebrewPort.exe` in a terminal. Expected output:

```text
PPU_HOMEBREW_RESULT=15
PPU_GUEST_BE_BYTES=18,52
```

The second line demonstrates that a PowerPC `stw` of `0x1234` stores bytes in big-endian order, and subsequent `lbz` instructions load `0x12` and `0x34`.

The build artifact includes the original `PPU_HOMEBREW.ELF`, generated `LumavunPPUHomebrewPort.cpp`, and compiled Windows x64 `LumavunPPUHomebrewPort.exe`.

## Test gates

- Python binary tests verify `std`/`ld`/`stw`/`lwz`/`lbz` and output, invalid guest addresses and alignment, unsupported DS variants and malformed ELF.
- Windows CTest runs the MSVC-built native program and requires the expected result plus big-endian byte evidence.
- Two additional native Windows test executables intentionally use invalid pointers (`0x1000`) and unaligned pointers (`0x2002`). Their harness requires **exact exit code 12**, not an arbitrary non-zero return or crash.
- Existing V0.1–V0.8.1 tests must continue passing before merge.

## What is still missing

There is no real PS3 ELF version fingerprinting, full PPU instruction set, multiple load segments, relocations, guest heap/stack, CellOS syscalls, SPU management, RSX graphics, audio, controllers, shader porting or playable Gundam Reborn. A retail EBOOT SELF is not decrypted or executed, and no copyright-protected game data is included.

The generic `lumavun_port build` command **continues to reject unsupported games**. Native demo translation proves only this limited homebrew subset, not universal PS3 porting.

Next engineering milestone: broader real PPU function-call control flow, ELF memory sections/relocations, and software-owned runtime replacement tests, using lawful and supported inputs.
