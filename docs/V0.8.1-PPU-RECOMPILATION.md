# V0.8.1: PPC64-to-Windows Static Recompilation Proof

This milestone verifies a real **PowerPC64 (PPU-style) instruction translation pipeline**. It does not port Dynasty Warriors: Gundam Reborn, run PS3 SELF files, or provide CellOS/RSX/SPU compatibility.

## Actual pipeline

1. `tools/ppu_homebrew.py` assembles an original, tiny **ELF64 big-endian PowerPC** with executable PT_LOAD bytes. Its machine code calculates the sum of integers 1 through 5.
2. `tools/ppu_static_recomp.py` validates ELF header/segment bounds, rejects unsupported instruction words, resolves a small set of static branch targets, and emits host C++ **per instruction**.
3. The Windows C++ compiler compiles the generated source into `LumavunPPUHomebrewPort.exe`.
4. Running the executable prints `PPU_HOMEBREW_RESULT=15` and returns exit code 0.

No PowerPC instruction interpreter or emulator is shipped with the generated EXE. The original PowerPC code's loop and subroutine branch-and-link are translated to native C++ control flow. CMake includes generated ELF and C++ alongside the native EXE as auditable evidence.

## Supported instruction subset

- `addi` with the special RA=0 zero operand.
- `add` (X-form XO 266, Rc=0).
- `cmpwi` (CR0 equality for this demo).
- `bc` with the specific BO/BI encoding used by `bne`.
- Relative `b` and `bl` within the sole code segment.
- `blr` through statically known branch-and-link return sites.
- One custom `sc` handler that prints the result.

The `sc` bridge is **invented for this original demo**, not a genuine PS3 syscall or ABI. This does not implement general function calls, floating point, vector instructions, memory loads/stores, dynamic linkage, PPU threading, SPU, RSX, CellOS, or game assets.

## Guardrails

- A maximum 1 MiB input, single ELF64 big-endian PowerPC executable segment of at most 4096 bytes, validated program headers.
- Reject unknown opcodes, out-of-segment jumps, malformed ELF, and SELF containers.
- Never overwrite the original input with output C++.
- Generated code has a one-million-step execution cap to prevent endless test loops.
- Unknown commercial games remain **BLOCKED** by the V0.4 porting pipeline.

## Tests

`tests/test_ppu_recomp.py` exercises the ELF generator and translator, compiling and running generated native C++ when GCC is available. GitHub Actions also builds and executes `LumavunPPUHomebrewPort.exe` with MSVC in Windows CTest; the expected output is exactly `PPU_HOMEBREW_RESULT=15`.

On Windows, extract the workflow ZIP and run `LumavunPPUHomebrewPort.exe` from a terminal to read the result.

## Next feasibility work

Real game-specific PPU recompilation requires an authorized and inspectable game ELF, title/version fingerprints, far broader instruction and memory handling, link/import resolution, system service replacements, SPU task handling, native RSX renderer, audio, controls, and comprehensive gameplay testing. None of that can be inferred from this deliberately small proof.
