# V0.8.5: PPC64 immediate instructions and region-checked guest memory

This milestone improves the original **self-authored PowerPC64 homebrew** translation prototype. It does not implement a PS3 OS, run a retail PlayStation executable, or port Gundam Reborn.

## What changed

The original ELF now executes three additional genuine 32-bit PowerPC instructions, each emitted as native C++ statements rather than decoded at runtime:

| PPC64 operation | Semantics supported |
| --- | --- |
| `addis` / `lis` | Sign-extend the 16-bit immediate, shift it by 16, add to the RA value (RA=0 uses literal zero), and wrap in 64-bit unsigned arithmetic |
| `ori` | OR the source GPR with the zero-extended 16-bit immediate |
| `xori` | XOR the source GPR with the zero-extended 16-bit immediate |

The demo constructs `0x12345678` with `addis + ori`, XORs `0x5678` back to `0x12340000`, writes the combined value to scratch guest memory using an original PPC `stw`, then uses `lwz` to verify the round-trip. Expected native result includes `PPU_IMMEDIATE_CHAIN=1`.

## Guest memory mapping

Backing storage is still a **fictional zero-initialized 64 KiB byte array**, but valid memory access is now restricted to these distinct writable regions:

- Runtime scratch: `0x2000` inclusive to `0x2100` exclusive.
- Every validated RW `PT_LOAD` section, mapped exactly to its ELF `p_vaddr..p_vaddr+p_memsz` range. In the existing fixture: `0x3000..0x3040` including zero-filled BSS.
- Homebrew stack: `0x6000..0x7000` (exclusive end), with initial SP `0x7000`.

No other guest data address can be loaded/stored even if it happens to fall inside the 64 KiB backing array. An operation that crosses a region end, violates alignment or accesses an unmapped hole returns **native exit 12**. This is not an implementation of real PS3 MMU, page tables, CellOS process segments, shared memory, or MMIO. Executable code has been statically translated and is not available for self-modifying guest memory access.

The ELF loader now rejects RW segments that collide with reserved scratch or stack areas. Relocations remain **symbol-free, fixed-bias `R_PPC64_RELATIVE` only**. An ELF section of type `SHT_DYNAMIC` or `SHT_DYNSYM` is explicitly rejected rather than silently accepted as if import resolution existed. `PT_DYNAMIC` is already unsupported by the PT_LOAD-only prototype.

## Reproducible native evidence

The Windows artifact includes `PPU_HOMEBREW.ELF`, generated C++ and `LumavunPPUHomebrewPort.exe`. Running the EXE should produce:

```text
PPU_HOMEBREW_RESULT=15
PPU_GUEST_BE_BYTES=18,52
PPU_STACK_RESTORED=1
PPU_ELF_RELOCATED=1
PPU_IMMEDIATE_CHAIN=1
```

Automated tests validate original PPC opcodes, actual native execution, ELF dependency rejection, stack/scratch collision, unmapped holes and region endpoints. Additional MSVC-compiled native traps must exit with **12**, not a generic nonzero error or crash. All prior PS1, launcher and PS2/PS3 analyzer tests remain regression gates.

## Unsupported functionality

No complete PPU instruction set, accurate condition registers/exceptions, production-grade permission model, dynamic import resolver, relocatable shared libraries, SELF decryption, SPU, RSX, CellOS, firmware or commercial game assets. The `lumavun_port build` safeguard continues refusing unsupported games.

### Next acceptance gate

Build a more realistic *lawful* PPU ELF with known symbols/import requirements and a reproducible instruction/function coverage report. Native gameplay of Gundam Reborn remains unverified and is not implied by this homebrew prototype.
