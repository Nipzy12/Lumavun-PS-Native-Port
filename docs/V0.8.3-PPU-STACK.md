# V0.8.3: PPC64 nested calls, link register and guest stack

This stage extends the original, self-authored **PPC64 homebrew ELF**, not a commercial PS3 game. It is an actual *static code translation* feature, still restricted to a tiny instruction subset and a fictional host ABI.

## New instruction behavior

- `mflr r12`: translated from PowerPC `mfspr r12,8`; copies the architectural link register to a guest GPR.
- `mtlr r12`: translated from `mtspr 8,r12`; restores the link register from a guest GPR.
- `stdu r1,-32(r1)`: checks the computed effective address, writes the old stack pointer as an 8-byte big-endian back-chain, then updates `r1`. A failed access returns **exit code 12** *without committing the stack-pointer update*.
- `ld r1,0(r1)`: restores the stack pointer from the validated back-chain.
- Existing statically resolved `bl` and `blr` now support the demo's two-level call chain when the code explicitly saves/restores LR. Neither the generated executable nor the original translation loads a runtime PowerPC instruction decoder.

Unsupported special purpose registers (anything other than LR / SPR 8) and invalid `stdu` RA=0 are rejected at translation time. The demo host initializes `r1=0x7000` within the *fictional* bounded 64-KiB guest RAM region, not a PS3 process address space.

## Code path

The original PPC64 instruction sequence:

1. Main calls worker via `bl`.
2. Worker copies LR, allocates a 32-byte frame, and saves the return address to guest RAM.
3. Worker computes 1+2+3+4+5 and calls the memory helper through another `bl`.
4. Nested helper allocates a second stack frame, performs big-endian `std/ld/stw/lwz/lbz` operations, then restores its stack pointer before `blr`.
5. Worker loads the saved LR, restores its frame's stack pointer, then `blr` returns to main.
6. The custom demo-only hostcall checks result, byte order and restored stack/LR state.

Expected native Windows output:

```text
PPU_HOMEBREW_RESULT=15
PPU_GUEST_BE_BYTES=18,52
PPU_STACK_RESTORED=1
```

## Verification

- CTest runs the MSVC-generated `LumavunPPUHomebrewPort.exe` and checks the stack marker.
- `tests/test_ppu_stack.py` verifies the encoded PPC instructions, successful two-level function call, and rejection of malformed SPR and `stdu` instructions.
- Negative tests intentionally attempt invalid stack frames outside mapped RAM and with non-8-byte-aligned addresses. Native code should return **12**, not crash or falsely report success.
- All previous PSP/PS1 inspection, PPU memory and launcher tests remain regression gates.

## Limitations

**Not a PS3 game port**: no retail ELF has been analyzed, no PS3 kernel, PPU ABI, CellOS services, ELF relocation processing, SPU, RSX graphics, game audio or Gundam Reborn menu/gameplay. The generic port builder continues to block unsupported retail titles. This demo does not model PPU exception behavior, multiple threads, real call-stack unwind rules or real OS stack initialization.

**Next:** ELF multiple PT_LOAD mappings/relocation metadata, larger instruction coverage, real ABI integration and game-specific function analysis using lawfully obtained inputs.

Reference for PowerPC encodings: [Go ppc64 instruction tables](https://go.googlesource.com/arch/+/refs/heads/master/ppc64/ppc64asm/tables.go), [PowerPC ISA Book I](https://powerpc.dev/general/PPC_Vers202_Book1_public.pdf).
