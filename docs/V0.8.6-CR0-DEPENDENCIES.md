# V0.8.6 — PowerPC64 CR0 control flow and read-only ELF dependencies

This milestone extends the **original self-authored PPC64 homebrew**, not Dynasty Warriors: Gundam Reborn. The current PS3 game port remains blocked.

## Actual static translation

The generated Windows C++ now models a **small subset of CR0** (condition register field 0):
- `cmpwi` / `cmpi cr0,L=0`: signed 32-bit comparison using the low 32 bits of a GPR and a sign-extended 16-bit immediate.
- `cmplwi` / `cmpli cr0,L=0`: unsigned 32-bit comparison against a zero-extended 16-bit immediate.
- `bc` with BO=12 (branch if CR bit true) or BO=4 (branch if CR bit false), and BI=0/1/2 for CR0 less-than, greater-than or equal. Branch targets must be aligned, remain within the verified code segment, and be relative.
- CR0's LT/GT/EQ bits are represented as 8/4/2 in the **demonstration host**. No CTR decrement, CR1–CR7, exception flags, SO bit, floating-point conditions, absolute branch targets or branch-and-link conditional forms are implemented.

The original PPC ELF exercises signed `-1 < 0`, unsigned `0xffffffff > 0`, equality with zero-filled BSS, then a not-equal branch. Each taken branch skips a machine-code failure marker. The Windows program reports **`PPU_CR0_BRANCHES=1`** only if all branches take the expected path.

Expected native output:

```text
PPU_HOMEBREW_RESULT=15
PPU_GUEST_BE_BYTES=18,52
PPU_STACK_RESTORED=1
PPU_ELF_RELOCATED=1
PPU_IMMEDIATE_CHAIN=1
PPU_CR0_BRANCHES=1
```

This demonstrates a limited, statically translated PPC instruction subset, **not** universal PowerPC instruction support or a PS3 game runtime.

## ELF import/dependency diagnostic

`tools/ppu_dependency_report.py` is a *separate read-only tool*. It can inspect bounded plain big-endian ELF64 PowerPC metadata:
- At most **32 MiB** of ELF file content, 128 program and section headers, 64 KiB dynamic-table bytes, 64 dependency names.
- Detect `PT_DYNAMIC` and parse `DT_NEEDED` names through a validated, file-backed `DT_STRTAB` address and `DT_STRSZ`.
- Report dynamic symbol sections, dynamic sections and relocation section counts.
- Output JSON with `REQUIRES_IMPORT_RESOLVER` or `NO_DYNAMIC_IMPORTS_OBSERVED`, `resolutionAttempted: false`, `nativeExecutableCreated: false`.
- Reject malformed bounds, missing termination, invalid string offsets and unsupported containers. It **does not** load, follow or resolve dependencies.

From the repository on Windows (Python required):

```powershell
python tools/ppu_dependency_report.py "D:\Games\AuthorizedPPU.ELF" --report "dependencies.json"
```

A commercial PS3 `EBOOT.BIN` in SCE SELF format is **not** decoded or decrypted by this tool. Even a reported `NO_DYNAMIC_IMPORTS_OBSERVED` says only that the selected metadata did not reveal dynamic dependencies, **not** that the program is portable.

The existing `tools/ppu_static_recomp.py` intentionally continues to **reject** dynamic library sections and `PT_DYNAMIC`, so recognizing a dependency name cannot inadvertently enable an unsupported game build.

## Test acceptance

- Windows native MSVC test: `native_ppu_cr0_branches` validates the sixth output marker.
- Python CR0 tests check real encoded PowerPC operands and signed/unsigned branches; unsupported CR field, CTR-dependent BO, or absolute branches are rejected.
- Python dependency tests use fully synthetic ELF and `DT_NEEDED` metadata, validate the library name without loading it, and reject malformed or oversized metadata.
- Full CTest continues exercising prior PS1 native demo, launchers, guest-memory traps and ELF relocation checks.

## Missing for Gundam Reborn

No verified game-specific executable; no full PPU CR/XER/CTR/call ABI, CellOS import resolver, SPU execution, RSX renderer, assets, audio or game input. There is no playable native Gundam Reborn build and no performance claim for AMD A4/Radeon R3.
